# Building our own ship models

Research snapshot: 2026-09-29. Recommendation: original procedural geometry for breadth, then reference-guided Blender models for Lion, Seydlitz and a period-appropriate frigate. A single side photograph is not enough to recover a hull: combine profile, deck/half-breadth and body sections with several photographs. Automation can loft sections and place fittings; historical interpretation and silhouette review remain human/art tasks.

## Reference candidates and rights checks

- **Naval Encyclopedia:** useful for discovery and visual comparison, not an assumed open asset library. Its [About page](https://naval-encyclopedia.com/about.php) describes original illustrations and unauthorized copying; the [poster catalogue](https://naval-encyclopedia.com/goodies/posters.php) is not a blanket redistribution license. Get explicit permission before tracing their artwork or using it as texture art.
- **HMS Lion:** [Royal Museums Greenwich technical plan](https://www.rmg.co.uk/collections/objects/rmgc-object-59786) is a strong geometry reference but lists Crown copyright; review the particular item's terms. [Historical photograph candidate](https://commons.wikimedia.org/wiki/File:HMS_Lion_(Lion-class_battlecruiser).jpg) has a public-domain rights statement on its file page.
- **SMS Seydlitz:** use the [Bundesarchiv warship-plan research guide](https://www.bundesarchiv.de/im-archiv-recherchieren/archivgut-recherchieren/nach-themen/schiffsplaene-von-kriegsschiffen/) to locate original drawings. [Model Monkey's profile scan](https://www.model-monkey.com/product-page/battlecruiser-sms-seydlitz-profile-view) is a discovery lead, not proof of commercial derivative rights. [Historical photograph candidate](https://commons.wikimedia.org/wiki/File:German_battlecruiser_SMS_Seydlitz_in_port_c1913.jpg).
- **Frigate:** [NARA sailing-ship records](https://www.archives.gov/research/military/navy-ships/sailing-ships.html) and the [1817 Constitution sail/profile plan](https://commons.wikimedia.org/wiki/File:18170000-US_NAI_102278445-draft_uss_constitution.jpg) are promising open-reference candidates. Constitution and Constellation (1797) belong to the original six-frigate design family, so Constitution plans are a useful family reference for Constellation, not an exact lines plan. [NHHC's Constellation record](https://www.history.navy.mil/research/histories/ship-histories/danfs/c/constellation-i.html) describes Humphreys/Fox's design and construction alterations. Adjust dimensions and fittings using Constellation-specific evidence; uniform scaling alone is not historical validation. French L'Insurgente needs French references. The 1817 drawing also needs a refit-year check against Nevis. [USS Constitution Museum's explanation](https://ussconstitutionmuseum.org/2016/09/21/humphreys/) describes hull-plan types. [RMG British frigate plans](https://www.rmg.co.uk/collections/objects/rmgc-object-387701) need item-specific rights review and date matching.

Access, download permission, public-domain status, permission to trace, and permission to redistribute are separate questions. File-page rights statements are leads, not a legal guarantee across jurisdictions. Original meshes do not automatically clear closely copied protected artwork. No reference images have been downloaded into or distributed with this implementation.

## Recommended Blender workflow

1. Choose ship **and refit year**, establish factual dimensions and an item-by-item provenance ledger (creator, archive ID, URL, rights statement, access date, permitted use).
2. Use cleared reference planes in a private authoring folder. Loft a half-hull from body sections; mirror it; fit sheer, flare, stem and stern against side/top views. Script repeated sections and modular fittings with Blender Python, rather than attempting one-shot image-to-3D reconstruction.
3. Reuse turrets, funnels, boats, tapered masts, yards and sail tiers. Review silhouette at the game's normal camera before adding fine detail. Model weathering as original shared trim textures; never paste archive photos onto the ship.
4. Author meters and a declared waterline/orientation; export game-scale normalization through the asset entry. Target the direction doc's 20–40k hero / ~5k mid triangles and 8 MB era pack budget, measured rather than assumed.
5. Bake Blender-only material graphs to glTF-compatible PBR textures. Export GLB, validate it, then encode textures to KTX2/Basis and optionally compress geometry with meshopt. [glTF overview](https://www.khronos.org/gltf/), [Three GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html).
6. Review normals, draft, scale, silhouettes, draw calls, loading failures and reduced-motion behavior in the actual viewport. Keep `.blend` sources and provenance separate from shipped references; publish model/texture credits with the asset.

Proceed now with the procedural kit. Next art experiment should be one small, original Blender hull blockout using cleared multi-view references—not procurement of an entire fleet, and not a promise that photos alone yield accurate geometry.

## Reproducible authoring and acceptance gate

- **One spec, two consumers:** keep the declarative hull/fitting spec as the source of truth. A future headless Blender script should consume a JSON export of that same spec, rather than maintain a second list of dimensions. Example intended command: `blender -b -P tools/build_ship.py -- --spec specs/lion.json` (**not implemented in this foundation**). Authoring stations can be added to the spec when cleared plans are available.
- **Units once:** metres in Blender; `MODEL_METERS_TO_WORLD` in `battle-presentation.js` is the single runtime conversion. It derives from the nominal 3× presentation enlargement and a 210 m representative capital ship occupying `SHIP_LENGTH`. Chart ranges remain compressed independently. Procedural specs are already world units: do not convert them again. Asset scale uses this factor once; waterline and orientation are applied inside an identity actor wrapper.
- **Tools:** this machine reports **Blender 5.2.2 LTS**. Pin that authoring version for the first experiment; retain the current pinned Three 0.186.1 / Vite 8.3.1 runtime. Before publishing authored assets, pin the exact glTF Validator, meshopt/gltfpack and KTX/Basis encoding versions in a reproducible tool manifest. No compression-tool version is asserted here because no model has yet been processed.
- **CI before registration:** add Khronos glTF Validator checks and an asset-budget report (hero 20–40k triangles, mid ~5k, ≤8 MB per era pack), with a small original compressed fixture. Generate medium LODs by controlled decimation and review silhouettes; use a simplified silhouette/impostor at the horizon. These authored-asset CI gates remain follow-up work, not completed tests.
- **Sign-off proposal:** Eric owns dimensions, refit-year/reference provenance and redistribution checks; Craig owns the in-game silhouette/light/moment acceptance. Record both approvals against the named reference sheet and screenshot set before registering each hero asset. This is a proposed responsibility split, not a claim of approval already received.
